# 야간 운전 시각 개선 시스템 요구사항 정의서

**문서 버전:** 2.1  
**최종 수정:** 2026-06-03  
**프로젝트명:** 야간 운전 시각 개선 시스템 (통합 모델 에디션)  
**상태:** 모델 통합 및 최적화 단계  
**핵심 결정:** Zero-DCE 기반 통합 모델 + Retinex 손실함수 + 20~30 FPS CPU 추론

---

## 1. 요약

이 프로젝트는 야간 운전 시 운전자의 시각을 개선하는 실시간 영상 처리 및 AI 기반 시스템을 개발합니다. 밝기 개선과 빛 번짐 완화라는 두 가지 핵심 과제를 **하나의 통합 AI 모델**로 해결합니다.

### 이전 버전 대비 개선사항
- **통합 모델 아키텍처**: Zero-DCE 기반 단일 모델 (MIRNet + CycleGAN 순차 처리 대신). MIRNet은 CPU에서 0.5~1 FPS에 불과하지만, Zero-DCE는 25~40 FPS 달성 가능
- **실시간 처리**: CPU에서 20~30 FPS 목표 (Colab GPU에서 학습)
- **Retinex 기반 손실함수**: Zero-DCE의 기본 손실함수를 확장하여 빛 번짐 억제 항 추가
- **CPU 최적화**: FP16 양자화 우선 적용 (품질 안전), INT8은 검증 후 선택적 적용
- **2단계 학습 전략**: LOL 사전학습 → 커스텀 도메인 파인튜닝 (실내/야외 도메인 불일치 해결)
- **구조화된 개발**: 학습(GPU)과 추론(CPU) 파이프라인 명확히 분리

## 2. 문제 정의

### 현재 도전과제
1. **빛 번짐 관리**: 야간 운전 중 맞은편 헤드라이트, 가로등, 반사면에서 발생하는 심각한 빛 번짐으로 시야 감소 및 사고 위험 증가
2. **저대비 장면**: 어두운 도로 환경에서 물체 감지를 위한 충분한 밝기 부족
3. **시간적 불일치**: 기존 AI 모델은 프레임 간 일관성 유지 어려움
4. **처리 지연시간**: 기존 구현은 저가형 하드웨어에서 실시간 처리 불가

### 영향
- 시야 손상으로 야간 운전 사고 확률 증가
- 과도한 빛 번짐으로 운전자 안구 피로 심화
- 현재 솔루션은 비싸거나 성능 부족

---

## 3. 프로젝트 목표

### 주요 목표
1. **빛 번짐 감소**: 고강도 광원의 빛 번짐 최소화하면서 장면 정보 보존
2. **밝기 개선**: 저노출 영역 시인성 증대 (노이즈 최소화)
3. **실시간 성능**: 표준 CPU에서 20 FPS 이상 처리 (Zero-DCE 기대치 25~40 FPS)
4. **AI 모델 성능**: 이전 버전 대비 20% 이상 품질 개선
5. **사용자 경험**: 50ms 이내의 지연시간으로 운전자에게 미지각 수준의 결과 제공

### 부수 목표
1. 다양한 차량 플랫폼 지원 (대시캠, 모바일, 임베디드 시스템)
2. 조명 조건에 따른 적응형 처리 활성화
3. 엣지 케이스 대응 메커니즘 제공

## 7. 기술 아키텍처

### 7.1 시스템 구성

```
┌─────────────────────────────────────────────────────┐
│            비디오 입력 (카메라/스트림)               │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│         프레임 버퍼 및 전처리                        │
│  - 색공간 변환 (RGB/YUV)                           │
│  - 해상도 정규화                                   │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│      AI 개선 모듈 (Zero-DCE, CPU)                 │
│  - 밝기 개선                                       │
│  - 빛 번짐 억제                                    │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│    후처리 및 톤 매핑                                │
│  - 색상 보정                                       │
│  - 해상도 업스케일 (192x192 → 원본)               │
│  - 시간적 일관성                                   │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│    출력 (개선된 비디오 + 메타데이터)               │
└─────────────────────────────────────────────────────┘
```

### 7.2 기술 스택 (확정)

#### 학습 환경
- **언어**: Python 3.8+
- **프레임워크**: PyTorch 1.13+ (통합)
- **모델**: Zero-DCE (~79K 파라미터, 7층 CNN)
- **손실함수**: Retinex 기반
  - 공간 일관성 (Spatial Consistency)
  - 노출 제어 (Exposure Control)
  - 색상 보존 (Color Constancy)
  - 조명 부드러움 (Illumination Smoothness)
  - 빛 번짐 억제 (Glare Suppression — 커스텀 추가)
- **학습 전략**:
  - 1단계: LOL Dataset 사전학습 (100 에포크, lr=0.0001, 배치=16)
  - 2단계: 커스텀 데이터 파인튜닝 (50 에포크, lr=0.00001, 배치=8)
- **환경**: Google Colab GPU (T4/V100)

#### 추론 환경
- **언어**: Python 3.8+
- **프레임워크**: PyTorch → ONNX Runtime (CPU 최적화)
- **입출력 해상도**: 원본 해상도 (예: 326x244); 내부 처리 192x192
- **양자화**: FP16 (주요), INT8 (품질 검증 후 선택)
- **목표 성능**: 표준 CPU에서 25~40 FPS (192x192 내부)

#### 데이터 및 전처리
- **주요 데이터셋**: LOL Dataset (485개 저조도 이미지 쌍)
- **커스텀 데이터**: Google Drive (600+ 이미지)
  - 포맷: `train_input_X.png` (완화 전) + `train_label_X.png` (완화 후)
  - 원본 해상도: 326x244 → 정규화 192x192
- **전처리**: OpenCV, NumPy
- **데이터 증강**: 랜덤 크롭, 좌우 반전, 밝기/대비 지터, 가우시안 노이즈, 회전

#### 웹 애플리케이션
- **백엔드**: Flask
- **비디오 I/O**: OpenCV (MJPEG 스트리밍)
- **배포**: CPU 추론 (GPU 가속 없음)

#### 기타 도구
- **모델 최적화**: ONNX, PyTorch 양자화 도구
- **성능 벤치마킹**: 커스텀 FPS/지연시간 측정 스크립트
- **버전 관리**: Git 시맨틱 버저닝

## 8. 데이터 요구사항 (확정)

### 8.1 학습 데이터
- **주요 출처**: LOL Dataset
  - 볼륨: 485개 저조도 이미지 쌍
  - 각 쌍: 원본 저조도 + 개선된 참고 이미지
  - 해상도: 가변 (학습 중 192x192로 정규화)
  
- **커스텀 데이터셋**: Google Drive 사용자 제공
  - 볼륨: 600+ 이미지
  - 포맷: `train_input_X.png` (원본 저조도) + `train_label_X.png` (개선된 참고)
  - 원본 해상도: 326x244 → 192x192로 정규화
  - 도메인: 야간 운전 시나리오 특화
  
- **전체 학습 데이터**: ~1,085+ 이미지 쌍

### 8.2 데이터 처리 파이프라인
- **증강 전략**:
  - 랜덤 크롭 (192x192)
  - 랜덤 좌우 반전
  - 밝기/대비 지터
  - 가우시안 노이즈 삽입 (강건성)
  - 랜덤 회전 (±5°)
  
- **학습/검증 분할**: 80/20

### 8.3 테스트 및 평가
- **검증 세트**: 전체 데이터셋의 20% (~217개 이미지)
- **평가 지표**:
  - **PSNR** (Peak Signal-to-Noise Ratio): > 20 dB
  - **SSIM** (Structural Similarity): > 0.85
  - **FPS** (Frames Per Second): ≥ 20 (CPU)
  - **지연시간**: < 50ms/프레임
  - **시각적 품질**: 주관적 아티팩트 평가

## 9. 성공 기준 (확정)

### 정량적 지표
1. **실시간 성능 (CPU)**: 표준 CPU에서 ≥20 FPS; Zero-DCE 기대치 25~40 FPS
2. **지연시간**: <50ms/프레임
3. **이미지 품질 지표**:
   - PSNR: > 20 dB (LOL SOTA 기준: MIRNet ~24 dB)
   - SSIM: > 0.85 (LOL SOTA 기준: MIRNet ~0.85)
4. **모델 크기**: <20MB (Zero-DCE ~79K 파라미터, 자연스럽게 경량)
5. **메모리 효율**: 추론 중 피크 메모리 <500MB
6. **모델 수렴**: 1단계 에포크 80~100 수렴, 2단계 에포크 30~50 수렴

### 기술적 지표 (Zero-DCE 통합 모델)
1. **밝기-빛 번짐 상충**: Retinex 손실함수로 균형
   - L_spa (공간 일관성): 가중치 1.0
   - L_exp (노출 제어): 가중치 10.0
   - L_col (색상 보존): 가중치 5.0
   - L_tvA (조명 부드러움): 가중치 200.0
   - L_glare (빛 번짐 억제, 커스텀): 가중치 λ (0.1~0.5, 파인튜닝 시 조정)
2. **FP16 양자화**: PSNR 손실 <1 dB 허용
3. **INT8 양자화**: PSNR 손실 <3 dB일 때만 적용, 아니면 스킵

### 정성적 지표
1. **시각 검사**: 색상 왜곡이나 아티팩트 없음
2. **시간적 일관성**: 프레임 간 부드러운 전환
3. **강건성**: 극한 저조도 및 빛 번짐 시나리오 처리
4. **통합 모델 효과**: 단일 모델이 순차 MIRNet + CycleGAN 파이프라인 이상 성능

## 15. 구현 참고사항

### 핵심 기술적 통찰력
1. **밝기-빛 번짐 상충**: 통합 모델은 Retinex 분해를 통해 밝기 개선(조명 맵 증가)과 빛 번짐 억제(반사 맵 최소화) 간의 근본적인 상충을 해결합니다. 손실함수가 두 구성 요소를 명시적으로 처리합니다:
   - **반사 맵 최소화**: 빛 번짐 아티팩트 감소
   - **조명 보존**: 장면 밝기 유지
   - **인지적 손실**: 시각적 품질 보장

2. **CPU 최적화 전략**: PyTorch + ONNX + FP16 양자화 + 프루닝을 통해 모델이 GPU 없는 CPU에서 30 FPS를 달성합니다. 이것은 전문 하드웨어 없는 차량 배포에 중요합니다.

3. **데이터 전략**: LOL Dataset (485개)과 사용자 데이터 (600+ 개)를 결합하면 다양성과 도메인 특화성을 제공합니다. 증강 파이프라인은 적당한 데이터량 (1,085+) 에도 불구하고 강건한 학습을 보장합니다.

4. **학습 vs 추론 분리**: 학습은 GPU(속도)를 활용하고 추론은 CPU(이식성)를 사용합니다. ONNX로 모델 내보내기는 플랫폼 간 호환성 및 최적화를 보장합니다.
